# CharacterHub 產品策略

**日期：** 2026-06-07  
**狀態：** 功能完成度 ≈ 20%，市場驗證 ≈ 0%  
**核心問題：** 還沒有人用，就一直設計功能。

---

## 現況診斷

> 市場驗證的價值比再做 10 個頁面高很多。

下一個里程碑不是「完成 Timeline」，而是：**找到 10 個願意把 OC 搬進來測試的人。**

---

## 三階段策略

### 第一階段：Demo 驗證

不開放註冊。不做社群。不做付費。

**做什麼：**
- 一個完整的「常夜國」範例企劃：3 個角色、10 個世界觀條目、5 個事件、關係圖、圖片
- 3 分鐘 Demo 影片：靈感 → 角色 → 世界觀 → 分享
- 投放到 Plurk、Discord、X、巴哈，問「如果有這種工具你會用嗎？」

**成功指標：** 有人說「幹，好想用」

---

### 第二階段：邀請制測試（10–20 人）

**目標族群（優先順序）：**
1. OC 創作者（噗浪/X/Discord/巴哈社群）
2. 文手
3. TRPG 玩家
4. 委託狂魔（委了 100 張圖的那種）

**觀察重點：** 他們第一個建立什麼？
- A. 直接建角色
- B. 先建世界觀  
- C. 先丟靈感

→ 這個答案決定產品的主要入口點設計。

---

### 第三階段：開源 + 官方服務

- Core 開源（MIT），社群自架
- 官方提供：雲端同步、分享頁、圖片空間
- 參考模型：Obsidian、Supabase、Cal.com

---

## MVP 最小範圍

```
Project → Character → Worldview → 分享頁
```

這樣就夠了。委託管理和其他功能等市場驗證後再做。

---

## 功能優先度

### 必做（市場驗證前）

| 功能 | 理由 |
|------|------|
| **Timeline 時間軸** | 對文手超重要。角色/世界觀/事件串成故事順序。 |
| **全站搜尋** | 角色、世界觀、事件、委託一起搜。像 Obsidian。 |
| **Hover Card** | 滑過名字跳出角色圖片/簡介，不用開新頁。 |
| **最近瀏覽** | 設定黨超需要，不用一直找。 |

### 推薦

| 功能 | 理由 |
|------|------|
| **圖庫 Gallery** | 聚合立繪/委託/設定圖，像 Pinterest，很多人先翻圖。 |
| **收藏夾** | 側欄快捷常用角色。 |
| **Command Palette（⌘K）** | 輸入名字直跳，輸入「新增」直接建立。超省時間。 |

### 進階（暫緩）

地圖頁、多人協作、版本紀錄

## 架構長期方向

### 條目統一化（重要）

目前分類在架構上是分開的（角色/世界觀），但本質都是「條目」：

```
角色     → 條目的一種
世界觀   → 條目的一種  
事件     → 條目的一種
靈感     → 條目的一種
```

**建議：** 遷移 SvelteKit 時，改用 Obsidian 式知識庫架構。好處是 Timeline、Map、Gallery、Relationship Graph 之後加進來時，不需要為每個新類型加特殊規則。現在還有機會在重寫時先解掉這個架構問題。

### Explorer UI 概念

```
📁 常夜國
├ 🎭 夜燈
├ 🎭 阿玄
├ 🌍 神社
├ 🌍 王城
├ 📖 守燈之約
└ 💡 神明吃名字
```

創作者是按企劃思考，不是按類別思考。

### 一鍵關聯（類 Notion @mention）

輸入 `@守燈人` → 自動關聯條目，不讓用戶手動找 ID。
