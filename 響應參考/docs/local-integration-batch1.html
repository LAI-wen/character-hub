03

建議實作順序

Order
  1. Auth session + ProjectMembership.role — Scope/權限的根；取代原型全域 viewer.role。
  2. ProjectRepository（list/get/switcher + viewerRole + stats）→ App Shell、Project Switcher、工作台、我的企劃、企劃總覽 可接。
  3. CharacterRepository（account library + body CRUD）→ 我的角色、Account Character Detail／Editor。
  4. ProjectCharacterLink（roster list + link CRUD + soft-remove）→ 企劃角色、Project Character context。
  5. 狀態 gate（Character.status / Link removed / Invalid context）→ 接上後逐頁打開 Archived／Removed／Forbidden。

Batch 2 預告（待 Phase 1.1）

Visual asset slice

Character Visual Asset Vertical Slice 待 Design Web Phase 1.1 完成後啟動。正式模型：Asset · AssetLink · AssetCollection · AssetCollectionLink · AssetAnnotation · ColorSwatch。Design Web 的 details[cid].art.visual 僅為 UI projection，非單一 JSON source of truth。Public Page Draft Preview 可先讀正式資料；Published Renderer／publish snapshot 留待 publish pipeline。

  • 與現有 Gallery schema 的潛在衝突（需本地確認）：原型 Gallery 已有 Asset／AssetLink 概念——Batch 2 的 AssetCollection／AssetCollectionLink／AssetAnnotation／ColorSwatch 應擴充而非另立一套；確認 Asset 的 role（avatar/hero/fullbody…）要存在 AssetLink 還是新 CharacterVisualRole。
  • R2 upload flow：init（取得 presigned）→ 前端直傳 → finalize（寫 Asset metadata + processingStatus）；非 ready 不可被 slot/album 引用（原型已模擬此 gate）。
  • Annotation：normalized region {x,y,w,h} 綁定特定 assetId（更換 slot 不搬移）；本地確認存獨立表或 Asset JSON 欄位。
  • ColorSwatch：含 sourceAssetId/sourceRegion/use/isPrimary/visibility；吸色結果先進「建議」不覆蓋。
本文件為規劃／盤點，不觸發 remote migration 或 production 部署。Design Web 持續提供 mapping 與 fixtures；正式 Repository／API／D1／R2 於本地實作。對照來源：handoff.html（§1 Route／§2 職責／§9 per-page）、uploads/api-contract-v1.md、uploads/schema-v1-draft.md。
